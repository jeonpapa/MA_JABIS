# 심평원 급여기준 DB 규칙 (항암제 공고 · 일반약제 고시 · KCD 질환 매핑)

> 2026-10-29 신설. 코드: `agents/hira_criteria/` · 테스트: `tests/test_hira_criteria_onco.py`, `tests/test_hira_criteria_drug.py`
> 목적: "어떤 질환(KCD)에 어떤 약제가 어떤 치료 순서로 급여되는가"를 원문 근거와 함께 바로 조회.

## 1. 원칙

- **최신만 유지**: 이력 테이블을 쌓지 않는다. 매 실행마다 최신 원문으로 파생 테이블을 통째로 다시 만든다.
  각 항목은 "그 약제/요법의 최신 공고·고시"로 검증한다.
- **원문 우선**: 원문 파일은 `data/hira_criteria/raw/`(sha256), 변환본은 kordoc(버전 고정 `KORDOC_VERSION`, 기본 4.24.16).
  `npx kordoc@^4` 같은 범위 지정 금지(레지스트리 최신 태그 ETARGET 실패 사례 2026-10-29).
- **dry-run 기본**: `pipeline onco|drug|kcd` 는 `data/hira_criteria/staging/*.db` 까지만. 본 DB 는 `pipeline apply …` 로만.
- **사람 정본 보호**: `indication_reimbursement`(Keytruda 체크리스트)에는 쓰지 않는다(data_contracts §1).
  자동 추출과 체크리스트가 다르면 보고만 한다. `criteria_disease_kcd.method='manual'` 행은 apply 가 지우지 않는다.
- **빈 결과 거부**: 스테이징 테이블이 비어 있으면 apply 거부(정본이 통째로 지워지는 사고 방지).
- **수집은 로컬**: HIRA 는 비한국/데이터센터 IP 를 400 으로 막는다(Fly 서버 크론 불가 → Aside/노트북).

## 2. 원천 (sources.py 가 매번 목록에서 최신을 찾는다)

| 구분 | 원천 | 비고 |

| 허가초과 항암요법 | 항암화학요법 > '허가초과 항암요법' xlsx | 신청기관 한정 인정 요법 + 불승인 요법 |

| KCD | 보험인정기준 > 자료실(청구관련기준자료) '배포용 상병마스터_YYMMDD.xlsx' | 2026.1.1~ KCD-9 |

## 3. 최신성 판정

- 항암: 통합본 기준일 ≥ 공고 게시판 최신 공고 시행일 → current. 아니면 stale(재실행 필요).
  최신 공고 요약의 `<신설>/<변경>` 요법은 결과에 **있어야**, `<삭제>` 요법은 **없어야** 정상.
- 일반약제: 책자 수록 이후 게시된 '(약제)' 고시로 같은 항목을 교체(`latest_basis='gosi_newer'`).
- 점검만: `python3 -m agents.hira_criteria.pipeline check onco drug kcd`

## 4. 항암 구조화 규칙 (onco_parser.py)

- 암종은 **목차 기준**으로 찾는다(본문 제목이 깨진 경우 대비 — 예: 10. 난소암 제목이 표 밖 두 줄).
- 표는 rowspan/colspan 을 격자로 펼친다. 한 연번 안에서 항암요법 칸이 `(제YYYY-N호: …)` 인 행은 공고 연혁,
  나머지는 투여대상·투여단계 변형(variant). 39번 표는 연혁이 '대상질환' 칸에 있다.
- 병합된 연번 칸(`24 25`)은 서로 다른 요법에 순서대로 배정. 연번 하나에 요법이 여럿이면 `multi_regimen_one_no` 플래그.
- 투여단계 우선순위: 표 '투여단계' 칸 > 소제목 '가. 투여단계: …' > 투여대상 **괄호 표기** `(2차 이상, 고식적요법)`.
  서술 속 '1차 백금 기반 …에 반응한' 은 투여단계가 아니다(유지요법 오판 회귀 방지).
- 투여요법 약어: N=선행(neoadjuvant), A=수술후보조(adjuvant), P=고식적(palliative), S=구제(salvage). 'N, A, P' 는 다중값.
- kordoc 은 단순 표를 Markdown 파이프 표로, 복잡한 표를 HTML 로 낸다 — 둘 다 파싱.
- 40번 '기타 항암제 병용요법'은 행마다 주요 암종(칸 누락 시 '허가사항' 문구)으로 암종을 판정하고, 각 암종 md 에 교차 연결.

## 5. KCD 매핑

- 암종→KCD 는 사람이 정한 사전(`onco_kcd.CANCER_KCD`)이며 실행 시 상병마스터 존재를 검증한다(없으면 실패).
- KCD 는 부위 기준이다. 형태학 암종(신경내분비·메르켈·횡문근육종·생식세포·신경모세포종·조직구증)은 대표 부위 코드 +
  confidence<0.8 → `needs_review`. 38번 전처치는 `not_applicable`, NTRK 등 암종불문은 `tumor_agnostic`.
- 일반약제는 이름 매칭 → (애매할 때) LLM 이 **주어진 후보 코드 중에서만** 선택. 존재하지 않는 코드 저장 금지.

## 6. 출력

- 테이블: `onco_criteria_regimen`(+`_drug`), `onco_offlabel_regimen`, `onco_offlabel_rejected`, `drug_criteria_item`,
  `criteria_disease_kcd`, `kcd_code`, `kcd_alias`, `hira_criteria_source`
- Markdown: `data/hira_criteria/md/onco/`(암종별 + 원문 전문), `md/drug/`(약제 항목별), `md/disease/`(KCD 3단별 색인)
- 출처 표기: 건강보험심사평가원, 공공누리 제4유형(출처표시·상업적 이용금지·변경금지). 외부 공개 시 원문 링크 병기.

## 7. 대쉬보드 '급여 기준' 화면 원칙 (페르소나 테스트 3회 반영, 2026-10-29)

- 결과·판정은 DB 원문에서 결정론적으로 만든다. LLM 은 질환 해석·조건 추출·질문 생성만 하며, 출력은 실재 값으로 검증하고
  타입을 보정한다(`_as_list`/`_as_int` — 형식이 달라도 500 금지).
- 항암 질환은 KCD 해부학 부위가 아니라 공고 암종 단위로 다룬다(두경부암에 '입술/혀' 를 묻지 않는다).
- 바이오마커는 환자 상태(양성/음성·이식 가능/불가). 반대 조건을 요구하는 요법만 빼고 조건 없는 요법은 남긴다.
  판단 창은 다음 마커 앞에서 끊고('gBRCA 변이 HER2-음성'), '변이가 확인된 환자는 …' 같은 조건부 문장은 요구 조건이 아니다.
  바이오마커·질환명은 약으로 해석하지 않는다(`_known_inn`, `_resolve_names`).
- 화면 순서: 판정(약별, 조건 요약 포함) → 한눈에 보기(치료 단계별 약 이름) → 상세. 약을 지정하면 기본은 '그 약만 보기'.
- 40번 표(기타 항암제 병용요법)는 '병용 신약 추가 요법 — 추가 약은 비급여, 기존 요법만 급여' 로 표현하고, 단계는 추가 약제
  허가 문구로 정한다(수술 전·후). 본표와 같은 요법은 본표만 보여준다.
- 비교는 칸(암종×치료 단계)·문단(질환) 단위로 맞추고, 띄어쓰기·구두점·글머리 번호·끝의 '(고시 제…호)' 는 차이가 아니다.
  '핵심 차이' 는 바뀐 부분이 든 문장 단위로 요약한다.

## 9. 허가초과 제외 · 4차 보완 (2026-10-29)

- **허가초과 항암요법(신청 병원 한정)은 급여가 아니므로 화면·판정·문서·집계에서 제외한다.** 원자료 테이블(`onco_offlabel_*`)과
  파이프라인 수집은 유지하되(재개 대비) `search.py` 는 노출하지 않는다. 판정 상태 `offlabel_only` 는 없다.
  (일반약제 기준 본문의 '허가사항 범위를 초과하여 … 인정' 문단은 급여 기준 자체이므로 그대로 둔다.)
- 40번 표: 급여기준 칸이 앞 연번에서 병합돼 내려온 행은 공통 비고(주석)만 남긴다(`_shared_notes`) — 예: 비소세포폐암 수술 전후 요법에
  lazertinib 의 EGFR 기준이 붙던 문제. 페이지 경계로 갈라진 허가사항 문장은 이어 붙인다(`_join_split_labels`, 자궁내막암 #38/#39).
  중첩 표 '연번|항암요법' 은 한 줄(`_flat_base_table`). `onco_parser.CELL_FIXES` 로 보정 전후를 비교할 수 있다.
- 투여대상이 '가. 1차 …/나. 2차 이상 …' 처럼 항목마다 차수가 다르면 환자 차수에 맞는 항목만 남기고 보여준다(`clause_lines`).
  (유지요법 올라파립+베바시주맙은 1차 전용이라 재발 2차 환자에게 나오지 않는다.)
- 혈액암 병용 행의 단계는 허가·대상 문구의 '새로 진단 / 재발·불응' 으로 구분한다.
- 질문의 약은 LLM 결과와 결정론 스캔(`_scan_drugs`)을 합쳐, 질문에 나온 순서대로(첫 약 = 비교 기준) 최대 3개. 질환 없이 약만
  입력하면 비교 버튼으로 안내.
- 비교 요약: 병용 표(40번)는 문장 조각 대신 '문구가 다름' 으로, 복사에는 고시번호·시행일 근거와 출처를 붙인다.
- 화면 상단 기준일: 시행 예정(오늘보다 뒤)이면 '시행 예정분 포함' 으로 표시.

## 10. 5차 보완 (2026-10-29)

- 일반어(`GENERIC_WORDS`: 병용·단독·비교·차이·치료 …)는 약 이름으로 풀지 않는다. '삼중음성 유방암 수술 전 키트루다 병용' 에서 '병용' 이 약 칩이 되던 문제.
- 판정이 '없음' 이면 같은 약이 **다른 조건**에서 급여되는 단계를 `elsewhere` 로 알려준다('조건 풀고 보기'). 약을 지정하면 바이오마커 되묻기는 생략.
- 비교 '핵심 차이' 는 **수치가 바뀐 부분이 있으면 '같음'이라고 하지 않는다.** 분류된 값(연령·체중·PD-L1·점수·용량·기간) → 분류 못 한 수치
  (양쪽에 서로 다른 값이 있을 때, `numeric_diff`) → 문구 차이 순. 금기·결핵 문단(상위 제목 포함)은 제외.
- 질환을 골라 비교할 때, 그 질환의 급여기준이 없는 약은 다른 질환 문단과 비교하지 않고 '해당 질환 기준 없음' 으로 둔다.
- 한 문장이 두 연번에 걸친 허가 문구는 바이오마커 판정을 연번별 부분(`extra.marker_text`)으로 한다(자궁내막암 #38 dMMR / #39 pMMR).
- 40번 표 병용 행: 비고의 '투여 단계: N차' 로 차수를 정하고, 환자 조건 일치 요법(`matches`)에도 병용 행을 '추가 약은 비급여' 표시로 포함한다.
- 연령 조항은 원문 순서로 보여준다. 카드에 '시행 예정' 배지(시행일이 오늘 이후).

## 11. 6차 보완 (2026-10-29)

- **바이오마커 판정은 괄호 속 영문 풀이를 빼고 읽는다**(`dMMR(mismatch repair deficient) 또는 MSI-H(…)가 없는` → MSS/pMMR). 펨브롤리주맙+렌바티닙은 pMMR 대상.
- **LLM 이 질의에 없는 조건을 붙이지 못한다**(`_guard_filters`): 질문에 해당 표현이 실제로 있는 치료 단계·차수·바이오마커만 남긴다
  ('자궁내막암' 만 입력했는데 수술 후 보조요법이 자동 적용되던 문제).
- 병용(40번) 행 허가 문구가 'N차 치료로서' 면 그 차수로 본다 — 1차 치료용 병용이 2차 비교·검색에 끼지 않게.
- 비교 수치 요약(`numeric_diff`)은 **같은 단위(주·개월·%…)로 양쪽에 서로 다른 값**이 있을 때만(한쪽 고유 기준 '3회·20점' 제외).
  급여 질환 차이 줄은 최대 8개. 금기 상위 제목 아래 문단 제외.
- 문단 비교: 한쪽만 '가. 투여대상' 제목이 풀려 서두가 비정상적으로 길면 통째 비교(`preface_skew`). 줄이 합쳐진 긴 1단계 제목('2. 허가사항 범위를
  초과하여 …')은 제목으로 인식해 앞 문단(베체트 장염)에 뒤 문단(괴저성 농피증 5mg/kg)이 섞이지 않게 한다.
- 요약 박스·카드 모두 시행일이 오늘 이후면 '시행 예정' 배지(`UpcomingBadge`).

## 12. 7차 보완 (2026-10-29)

- 40번 표: 변환 중 위아래 병합된 연번 칸(예: '26' 하나가 26~29 요법 4개를 덮음)은 **다음 연번이 요법 수만큼 뒤에 있을 때** 순서대로 번호를 복원한다
  (`renumbered_by_sequence`). 복원 뒤 `stats.numbering_gaps` 는 비어야 한다.
- 비교의 수치·기간은 **원문 소제목 기준**으로 분류한다: `1) 투여대상` 아래 → 이전 치료 기간/증상 지속, `2) 평가방법` 아래 → 평가 시점,
  투여방법·교체투여·금기 아래는 제외. 그래서 속성 추출은 diff 가 아닌 **원문 블록 텍스트**(`block["orig"]`)로 한다(diff 정규화가 소제목을 지우므로).
  기간 범위('12~14주')는 범위째 보존, '1,000주울' 같은 숫자는 기간이 아니다.
- 비교 줄 머리는 제목이 없으면 두 약이 함께 급여하는 **질환 이름**(예: 아토피성 피부염)을 쓴다. 긴 제목은 46자에서 말줄임.
- '한눈에 보기'에 병용 신약 추가 요법을 단계별로 포함하고 시행 예정 항목은 ●MM-DD 로 표시한다.

## 13. 운영 반영 방식 (2026-10-30)

- 운영 DB 는 살아 있는 DB 라 로컬 DB 를 덮어쓰지 않는다. 급여 기준 **새 테이블만** 이미지 시드(`seed/hira_criteria/`)로 싣고 부팅 때 적재한다
  (`scripts/build_hira_criteria_seed.py` → `scripts/seed_hira_criteria.py`, 기본 dry-run, `--apply --if-changed` 멱등).
- 적용은 한 트랜잭션·실패 시 롤백, 기존 파생 테이블 백업(`data/hira_criteria/backup/`)·undo JSON 기록, `manual` 질병코드 보존,
  같은 이름 테이블의 열 구성이 다르면 거부. 허가초과 테이블은 시드에 넣지 않는다.
- 데이터를 갱신하면 시드를 다시 만들어야 운영에 반영된다(`build_hira_criteria_seed.py --check` 가 오래됨을 알려 준다). 절차: `docs/ops/HIRA_CRITERIA_DEPLOY.md`.
